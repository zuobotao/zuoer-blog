Varieties.csv

4,2,Carrot,胡萝卜

OrientDB ETL工具仅需要一个JSON文件即可将ETL流程定义为Extractor，将在管道中执行的Transformer列表，以及一个Loader，以将图形元素加载到OrientDB数据库中。

以下是两个包含ETL的文件，分别用于导入科目和品种。

Subject.json ETL文件

````
```
{
  "source": { "file": { "path": "C:/orientdb-data/Subject.csv" } },
  "extractor": { "csv": {} },
  "transformers": [
    { "vertex": { "class": "Subject" } }
  ],
  "loader": {
    "orientdb": {
       "dbURL": "remote:localhost/MockWarfare-01",
       "serverUser": "root",
       "serverPassword": "root",
       "dbType": "graph",
       "classes": [
         {"name": "Subject", "extends": "V"},
         {"name": "Varieties", "extends": "V"},
         {"name": "ascription", "extends": "E"}
       ], "indexes": [
         {"class":"Subject", "fields":["id:integer"], "type":"UNIQUE" }
       ]
    }
  }
}
```
````

我们在Subject.id字段上创建了索引，以确保没有重复，并且在创建的边上查找（见下文）将足够快。

Varieties.json ETL文件

````
```
{
  "source": { "file": { "path": "C:/orientdb-data/Varieties.csv" } },
  "extractor": { "csv": {} },
  "transformers": [
    { "vertex": { "class": "Varieties" } },
    { "edge": { "class": "ascription",
                "joinFieldName": "SubjectId",
                "lookup": "Subject.id",
                "direction": "in"
            }
        }
  ],
  "loader": {
    "orientdb": {
       "dbURL": "remote:localhost/MockWarfare-01",
       "serverUser": "root",
       "serverPassword": "root",
       "dbType": "graph",
       "classes": [
         {"name": "Subject", "extends": "V"},
         {"name": "Varieties", "extends": "V"},
         {"name": "ascription", "extends": "E"}
       ], "indexes": [
         {"class":"Varieties", "fields":["id:integer"], "type":"UNIQUE" }
       ]
    }
  }
}
```
````

该文件与上一个文件相似，但是Edge转换器完成了该工作。由于在CSV中找到的链接朝相反的方向（Varieties-> Subject），虽然我们要直接建模（Varieties-> Comment），所以我们使用了“ in”方向（默认始终为“ out”）。

接下来我们说下ELT json文件的各种参数吧

OrientDB通过一个在执行时调用的JSON配置文件来管理ETL模块的配置。

````
```
{
  "config": {
    <name>: <value>
  },
  "begin": [
    { <block-name>: { <configuration> } }
  ],
  "source" : {
    { <source-name>: { <configuration> } }
  },
  "extractor" : {
    { <extractor-name>: { <configuration> } }
  },
  "transformers" : [
    { <transformer-name>: { <configuration> } }
  ],
  "loader" : { <loader-name>: { <configuration> } },
  "end": [
   { <block-name>: { <configuration> } }
  ]
}
```
````

- "config" 管理流程的任何组件使用的所有设置和上下文变量。
- "source" 管理要处理的源数据。
- "begin"定义进程开始时按顺序执行的block列表。
- "extractor"管理extractor设置。
- "transformers"定义要在管道中执行的transformers列表。
- "loader"管理loader设置。
- "end"定义要在过程完成时按顺序执行的block的列表。

# config

ETL模块将"config"块中声明的所有值绑定到执行上下文，并且可用于ETL处理。ETL流程还使用一些特殊变量。

|  |  |  |  |
| --- | --- | --- | --- |
| 变量 | 描述 | 类型 | 默认值 |
| "log" | 定义全局日志记录级别。接受的级别为：NONE，ERROR，INFO，和DEBUG。此参数对于调试ETL流程或单个组件很有用。 | string | INFO |
| "maxRetries" | 定义在加载程序引发ONeedRetryException并同时修改同一记录时允许的最大重试次数。 | integer | 10 |
| "parallel" | 定义ETL模块是否使用所有可用内核并行执行管道。 | boolean | false |
| "haltOnError" | 定义ETL模块在遇到无法管理的错误时是否停止该过程。设置false为时，如果发生错误，该过程将继续。它报告导入结束时遇到的错误数。此功能在2.0.9版本中引入。 | config | true |

# source

当OrientDB执行ETL模块时，源组件将定义要提取的数据的源。对于某些提取器（如JDBCExtractor），它在没有源代码的情况下工作，因此使此组件成为可选组件。OrientDB中的ETL模块支持以下类型的源：

- "file"
- "input"
- "http"

# extractor

当OrientDB执行ETL模块时，提取器组件将处理从源中提取的数据。它们是ETL流程的第一部分。OrientDB中的ETL模块支持以下提取器：

- Row
- CSV
- JDBC
- JSON
- XML

本部分内容过多，先简单说下，以后将会单独拿出一章单独讲解！

## csv

当ETL模块运行CSV提取器时，它将解析格式化为Apache Commons CSV的文件，并将数据提取到OrientDB中。该组件是在2.1.4版中引入的，在OrientDB的较早版本中不可用。

- 组件名称：csv
- 输出类别： [ ODocument ]

**句法**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| 参数 | 描述 | 类型 | 强制性的 | 默认值 |
| "separator" | 定义列分隔符。 | char |  | , |
| "columnsOnFirstLine" | 定义第一行是否包含列描述符。 | boolean |  | true |
| "columns" | 为名称和（可选）要写入的类型定义数组。 | string array |  |  |
| "nullValue" | 在文件中定义空值。 | string |  | NULL |
| "dateFormat" | 定义在从文件解析日期时使用的格式。 | string |  | yyyy-MM-dd |
| "dateTimeFormat" | 定义在解析日期和文件中的时间时使用的格式。 | string |  | yyyy-MM-dd HH:mm |
| "quote" | 定义字符串字符定界符。 | char |  | " |
| "skipFrom" | 定义要跳过的行号。 | integer |  |  |
| "skipTo" | 定义要跳过的行号。 | integer |  |  |
| "ignoreEmptyLines" | 定义是否应忽略空行。 | integer |  | false |
| "ignoreMissingColumns" | 定义是否应忽略空列。 | integer |  | false |
| "predefinedFormat" | 定义要使用的CSV格式。 | string |  |  |

- 对于"columns"参数，通过将其后缀到值来指定类型。指定类型可以保证更好的性能。
- 对于"predefinedFormat"参数，可用的格式有：Default，Excel，MySQL，RFC4180，TDF。

**例子**

- ODocument使用逗号作为分隔符，将CSV提取的行提取到类，将其视为NULL空值，并跳过第二到四行：

````
```
  { "csv":
      {  "separator": ",",
         "nullValue": "NULL",
         "skipFrom": 1,
         "skipTo": 3
      }
  }
```
````

从MySQL导出的CSV中提取行：

````
```
{ "csv":
    {  "predefinedFormat": "MySQL"}
}
```
````

使用默认格式（N/A用作null值和自定义日期格式）从CSV提取行：

````
```
{ "csv":
    {  "predefinedFormat": "Default",
       "nullValue" : "N/A",
       "dateFormat" : "dd-MM-yyyy",
       "dateTimeFormat" : "dd-MM-yyyy HH:mm"
    }
}
```
````

使用默认格式从CSV提取行，使用N/A自定义日期格式，自定义dateTime格式和列类型映射作为空值：

```
{ "csv":
    {  "predefinedFormat": "DEFAULT",
       "nullValue" : "N/A",
       "dateFormat" : "dd-MM-yyyy",
       "dateTimeFormat" : "dd-MM-yyyy HH:mm",
       "columns": ["name:string","createdAt:date","updatedAt:dateTime"]
    }
}
```

# transformers

当OrientDB运行ETL模块时，转换器组件在管道中执行修改数据，然后再将其加载到OrientDB数据库中。对接收到的输入和返回输出进行操作。

- CSV
- FIELD
- LOAD
- MERGE
- VERTEX
- CODE
- LINK
- EDGE
- FLOW
- LOG
- BLOCK
- COMMAND

这块咱们重点讲解VERTEX和EDGE

## VERTEX

当ETL模块运行Vertex Transformer时，它将ODocument输入转换为output OrientVertex。

组件说明。

- 组件名称：**顶点**
- 支持的输入类型：[ **ODocument**，**OrientVertex** ]
- 输出：**OrientVertex**

**句法**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| 参数 | 描述 | 类型 | 强制性的 | 默认值 |
| "class" | 定义要使用的顶点类。 | string |  | V |
| "skipDuplicates" | 定义是否跳过重复项。当类具有UNIQUE约束时，ETL将忽略重复项。 | boolean |  | false |

示例

````
```
 {
      "class": "Varieties",
       "skipDuplicates": true
    }
```
````

## EDGE

当ETL模块调用Edge Transformer时，它将在当前顶点与查找返回的所有顶点之间的一个或多个边缘中转换连接值。可以根据索引或进行查找SELECT。

组件说明。

- 组件名称：**EDGE**
- 支持的输入类型：[ **ODocument**，**OrientVertex** ]
- 输出：**OrientVertex**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| 参数 | 描述 | 类型 | 强制性的 | 默认值 |
| "joinFieldName" | 定义包含连接值的字段。 | string | 是 |  |
| "direction" | 定义边缘方向。 | string |  | out |
| "class" | 定义边缘类。 | string |  | E |
| "lookup" | 定义要在其上执行查找的索引或SELECT。 | string | 是 |  |
| "targetVertexFields" | 定义要在其上设置目标顶点的字段。 | object |  |  |
| "edgeFields" | 定义要设置的字段。 | object |  |  |
| "skipDuplicates" | 定义UNIQUE在out和in属性上均设置约束时是否跳过重复的边。 | boolean |  | false |
| "unresolvedLinkAction" | 定义在尚未解决联接的情况下执行的操作。 | string |  | NOTHING |

示例

````
```
{
  "class": "ascription",
  "joinFieldName": "SubjectId",
  "lookup": "Subject.id",
  "direction": "in"
            }
```
````
