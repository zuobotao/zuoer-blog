1.分区插入时锁表处理

异常提示：

```
Error while processing statement: FAILED: Error in acquiring locks: Locks on the underlying objects cannot be acquired. retry after some time
```

```
查数据分区是否存在表锁[2]
```

```
标准
show locks tableName partition(partitionname= 'partitionvalue')
show  locks 表名 partition(分区标识='分区名')
示例
show locks dws_XXX_m_i_zuoyang partition(month = '2020-03')


我这里在插入【月份粒度】分区为 '2020-03' 的时发生上述异常，
以此操作查看是否锁表
```

```
解锁[3]
```

```
标准
unlock table tableName partition(partitionname= 'partitionvalue')
unlock table 表名 partition(分区标识='分区名')
示例
unlock table dws_XXX_m_i_zuoyang partition(month = '2020-03')


我这里遇到无法插入分区数据的锁表情况，通过上述解锁操作后已经处理掉
```

造成原因[4][5]

```
Two-phase locking (2PL)
This is the most widely used protocol. There are two rules:
If a transaction T wants to read (respectively, modify) an object, it first requests a shared (respectively, exclusive) lock on the object.
A transaction can’t acquire new locks after it starts to release already acquired locks.
```

```
翻译
```

```
两相锁定（2PL）
这是使用最广泛的协议。有两条规则：
如果事务T想要读取（分别修改）对象，它首先请求对象上的共享（分别独占）锁。
事务在开始释放已获取的锁后无法获取新锁。
```

是由于我在操作插入过程中，强行中断SQL脚本时正在操作中的事务锁没有被释放造成的。

1. 修改字段类型[6]

```
标准
ALTER table tableName CHANGE column columnName newColumnName TYPE
ALTER table 表名 CHANGE column 需要修改的字段名 新的字段名 字段类型
示例
ALTER table dws_XXX_m_i_zuoyang CHANGE column name name STRING

```
