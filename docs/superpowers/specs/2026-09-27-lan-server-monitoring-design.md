# 局域网服务器监控页设计

## 目标与范围

为运行博客和 Ledger 的 Termux 手机服务器提供一个仅供局域网访问的实时监控页。页面展示手机资源、博客与游戏服务健康状态、Tunnel 进程状态，以及 Ledger 多人房间的汇总状态。优先满足手机浏览器可读、故障可定位、持续运行开销低。

监控只读，不控制、重启或修改被监控服务。首版不提供告警、账号体系、历史数据保存或公网访问。

## 方案选择

采用独立监控服务，与现有博客、游戏和房间服务分开监听。替代方案是在公开的房间服务端口上加入管理页面，或部署 Prometheus/Grafana。前者扩大公网服务的攻击面，后者对单台 Termux 手机增加不必要的资源与维护成本。

## 组件与端口

- 监控网页及 JSON 接口：Termux Python 标准库实现，监听 `8765`，仅接受局域网来源。
- 房间内部统计接口：由 Ledger 房间服务提供，单独监听 `127.0.0.1:8788`。不复用已通过 Cloudflare Tunnel 暴露的 `8787` 端口。
- 被监控服务：博客 `8080`、Ledger 前端 `8081`、房间 HTTP/WebSocket 服务 `8787`，以及 `cloudflared` 进程。
- Termux 开机启动：新增独立的 `20-zuoer-monitor` 脚本，不替换现有 `10-zuoer-server`，以免覆盖已经在设备上运行的游戏和房间启动配置。

`8765` 和 `8788` 均不加入 Cloudflare Tunnel 路由。监控服务在网络接口上监听时，只接受 RFC1918 私有 IPv4 与 IPv6 ULA 来源；其他来源返回拒绝。内部房间统计接口仅绑定 loopback。手机 LAN 地址由用户在同一局域网内访问。

## 展示数据

系统资源：CPU 利用率、内存使用量、博客数据所在文件系统的用量、系统运行时长。CPU 温度仅在 Termux 可读到有效传感器时显示，不可读不视为故障。

服务状态：分别探测博客首页、Ledger 前端首页、房间服务 `/health`，并检查 Tunnel 进程是否存在。探测均在本机访问环回地址，使用有限超时；一个服务失败不影响其他卡片更新。显示最近采样时间与单项错误状态。

房间汇总：显示 waiting、starting、playing、paused、finished、closed 房间数，和当前 WebSocket 房间连接总数。数据只从内存房间仓库聚合，不返回昵称、房间名、房间码、玩家 ID、会话 ID、IP、token 或对局内容。该数值反映当前进程内存状态，房间服务重启后房间本身也会清空。

## 数据流

浏览器每 5 秒请求监控服务的 `/api/metrics`。监控服务读取 `/proc` 与目标目录文件系统用量，探测三个本机 HTTP 服务和 Tunnel 进程，并从 `127.0.0.1:8788` 获取房间汇总。内部房间统计端点以不可变聚合快照响应，不暴露仓库对象。

页面最多在浏览器内存中保留最近 5 分钟的采样，用于短时趋势显示；刷新或关闭页面后丢弃。服务器不保存监控样本，不写昵称、用户标识或访问日志中的查询参数。

## 页面与交互

沿用博客现有简洁、暖纸色设计语言，针对手机竖屏优先。首屏突出整体状态和最后更新时间，之后依次展示系统资源、博客/游戏/房间/Tunnel 服务卡片、房间状态汇总与短时曲线。页面只读，无控制按钮；失败状态直接标记具体服务及原因，不把缺失数据伪装成零。

## 错误与安全

- 监控服务和房间内部接口有独立可配置端口；端口冲突或启动失败写入 Termux 启动日志，不影响博客、Ledger 或 Tunnel 启动。
- 内部统计接口只监听 loopback，并返回汇总字段白名单。公网 Tunnel 继续只路由现有服务，不增加监控 hostname 或路径。
- 监控服务按来源地址限制 RFC1918/IPv6 ULA；非私有地址得到 403。不得用 `X-Forwarded-For` 作为允许依据。
- `/proc`、温度传感器或进程信息不可用时，将该指标显示为 unavailable，并继续提供其他数据。
- 仅使用 Python 标准库，不增加运行时依赖或外部遥测。

## 验收标准

1. 连接手机同一局域网的设备可打开 `http://<手机局域网地址>:8765/`，显示系统资源、四项服务状态和房间汇总；浏览器不访问公网第三方服务。
2. 博客、Ledger 前端、房间服务、Tunnel 任一项停止时，对应卡片显示离线或错误，其他数据继续刷新。
3. 创建、加入、退出及切换游戏状态时，聚合房间数与连接数随状态更新，响应中不含房间或玩家个人信息。
4. loopback 统计接口不能从 LAN 访问；监控端口不出现在 Cloudflare Tunnel 配置中，非私有来源请求被拒绝。
5. 监控进程通过独立 Termux:Boot 脚本幂等启动；反复执行启动脚本不会产生重复进程。
6. Python 单测覆盖指标解析、服务超时与来源地址过滤；Ledger 测试覆盖房间统计聚合；博客 `check`、`build`、`test` 均通过。

## 不在首版范围

持久化历史、告警通知、远程管理动作、房间详情页、玩家昵称与游戏内容、手机温度保证、以及将监控接入公共域名。
